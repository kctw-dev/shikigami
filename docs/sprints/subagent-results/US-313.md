```
  |-- docs/sprints/sprint-checkpoint.json 不存在
  |     → [CHECKPOINT-NEW] 正常開始（無先前 checkpoint）
  |-- 存在且所有 Story status = "completed"
  |     → [CHECKPOINT-DONE] 所有 Story 已完成，觸發 sprint-review
  +-- 存在且有未完成 Story（status = "in-progress" 或 "pending"）
        → [CHECKPOINT-RESUME] 偵測到未完成 checkpoint，從斷點繼續
        → 跳過所有 status = "completed" 的 Story（已完成，不重做）
        → 從第一個 status ≠ "completed" 的 Story 開始執行
```

輸出標記：
- `[CHECKPOINT-NEW]` — 無先前 checkpoint，正常開始
- `[CHECKPOINT-RESUME]` — 從斷點繼續
- `[CHECKPOINT-DONE]` — 所有 Story 已完成

### AC-3：孤兒 Claim 清理

**狀態：PASS**

新建 `hooks/claim-cleanup.sh`：

**功能：**
- 列出所有 `refs/claims/*` 遠端 ref
- 對每個 ref 檢查 commit timestamp
- 超過 TTL（預設 2 小時 = 7200 秒）→ 呼叫 `hooks/release-issue.sh` 清理
- 輸出 `[CLAIM-CLEANUP] <N> 個 stale claim 已清理`

**參數：**
- `--dry-run`：僅列出 stale claims，不實際清理
- `--ttl <秒>`：自訂 TTL（預設 7200，供測試縮短使用）

**容錯設計：**
- git 不可用 → 輸出 `[WARN]`，跳過清理，exit 0
- 無法連接 remote → 輸出 `[WARN]`，跳過清理，exit 0
- 無法取得 commit 時間 → 保守策略：輸出 `[WARN]`，跳過該 ref（不誤刪）
- release-issue.sh 不可用 → 直接 git push --delete

**使用方式：**
```bash
# 手動清理
bash hooks/claim-cleanup.sh

# Dry-run（僅列出）
bash hooks/claim-cleanup.sh --dry-run

# 搭配 schedule skill 定期清理
# 每 2 小時執行一次
bash hooks/claim-cleanup.sh
```
