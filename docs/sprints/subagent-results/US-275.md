# US-275 — Sprint Planning 並行衝突防護

**Story**: US-275 (#277)
**Sprint**: 100
**Status**: PASS

## 修改摘要

### 問題
多個 session 同時執行 Sprint Planning 時，PO Round 2 可能取得相同的 Sprint 編號，導致 `sprint_N.md` 被覆蓋或衝突。

### 解法
在 `po-prompt.md` PO Round 2 職責區塊中，建立前加入並行衝突防護流程：

1. **git pull** — 同步最新狀態，取得其他 session 已 commit 的 sprint 文件
2. **掃描最大編號** — `ls docs/sprints/sprint_*.md | grep -oP 'sprint_\K\d+' | sort -n | tail -1`
3. **計算 next_N** — max_N + 1
4. **檔案存在性檢查** — 若已存在則自動遞增並輸出 `[SPRINT-CONFLICT]` WARN 日誌
5. **立即 git add + git commit** — 縮小競態窗口

### AC 驗收

| AC | 狀態 | 說明 |
|----|------|------|
| AC-1：並行衝突防護 | PASS | po-prompt.md 加入 git pull + 存在性檢查 + 自動遞增 |
| AC-2：regression 驗收 | PASS | 衝突時輸出 `[SPRINT-CONFLICT]` WARN 日誌 |
| 非功能：正常流程無延遲 | PASS | 無衝突時僅增加一次 git pull |
