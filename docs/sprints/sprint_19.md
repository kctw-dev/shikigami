## Acceptance Criteria

### Retro #53（Issue #53）：schedule skill — skill name 字元白名單驗證

**User Story**
As a framework user, I want the schedule skill to validate skill names against a strict whitelist regex before any execution, so that malicious or malformed skill names cannot be used to exploit the scheduling system.

**背景**
Sprint 18 Retro 識別：schedule skill 的 Pre-flight 入口未對 skill name 進行字元驗證，存在路徑注入或特殊字元攻擊的安全缺陷。本 Retro Action Item 補入白名單驗證。

| # | 類型 | 條件 | 通過標準 |
|---|------|------|----------|
| AC1 | [靜態] | 白名單正則驗證 | Pre-flight 入口加入 `^[a-z0-9][a-z0-9-]{0,63}$` 正則驗證；非法字元輸入時 Pre-flight 阻擋並輸出明確錯誤訊息，不生成任何檔案 |
| AC2 | [靜態] | 測試套件覆蓋 | 測試套件新增非法字元場景覆蓋（至少包含：特殊字元、空格、大寫字母、路徑分隔符號等非法輸入案例） |

**MoSCoW**：Must / **Size**：S / **Points**：1
**來源**：Sprint 18 Retro / GitHub Issue #53
**ADR-003**：適用（修改 schedule skill）

### Retro #54（Issue #54）：schedule skill — 模板品質強化（set -euo pipefail + 備份安全）

**User Story**
As a framework user, I want the cron scripts generated by the schedule skill to use safe shell scripting practices and secure temp file handling, so that script execution failures are caught early and backups are protected from race conditions.

**背景**
Sprint 18 Retro 識別：生成的 cron 腳本模板有兩個品質問題：(1) 使用 `set -uo pipefail` 缺少 `-e`，錯誤不會立即中止腳本；(2) crontab 備份使用固定路徑，存在競態條件（race condition）風險。

| # | 類型 | 條件 | 通過標準 |
|---|------|------|----------|
| AC1 | [靜態] | 強化 set 選項 | 腳本模板中 `set -uo pipefail` 改為 `set -euo pipefail`，確保任何指令失敗立即中止腳本執行 |
| AC2 | [靜態] | 安全備份機制 | crontab 備份改用 `mktemp` 生成唯一臨時路徑，並對備份檔案執行 `chmod 600` 保護；消除固定路徑的競態條件風險 |

**MoSCoW**：Must / **Size**：S / **Points**：1
**來源**：Sprint 18 Retro / GitHub Issue #54
**ADR-003**：適用（修改 schedule skill 模板）

### US-30（Issue #48）：PO subagent 多輪派遣時 Story 內容偏離修正機制

**User Story**
As a QA subagent, I want a mechanism to detect and reject content drift between PO Round 1 and Round 2 outputs, so that Story ID, titles, and ACs remain consistent across planning rounds and do not silently mutate.

**背景**
Sprint 17 Retro 識別：PO 在 sprint-planning 中被派遣兩輪（Round 1 Story 選取、Round 2 確認），兩輪之間存在 Story 內容漂移風險：Story ID 不符、標題被改寫、AC 被新增或刪除，而 QA 可能靜默接受導致偏離未被察覺。本 Story 建立防漂移約束與告警機制。ADR-003 適用。

| # | 類型 | 條件 | 通過標準 |
|---|------|------|----------|
| AC1 | [靜態] | 防漂移約束 | `skills/sprint-planning/SKILL.md` §6 步驟 4（PO 第二輪）新增防漂移約束：PO Round 2 回傳的 Story 清單需與 Round 1 的 Story ID + 標題欄位完全一致 |
| AC2 | [靜態] | 偏離判定規則 | SKILL.md 明確記載偏離判定規則：Story ID 不符、標題被改寫、AC 被新增/刪除，任一情形即為偏離 |
| AC3 | [靜態] | 告警處理路徑 | SKILL.md 記載：偏離時 QA 告警並要求 PO 重新派遣，不靜默接受；告警格式須包含偏離項目清單 |

**MoSCoW**：Must / **Size**：S / **Points**：1
**來源**：Sprint 17 Retro / GitHub Issue #48
**ADR**：ADR-003 適用（修改 skills/sprint-planning/SKILL.md）

### US-36（Issue #50）：Planning + Execution 序列排程 — 避免平行衝突

**User Story**
As a framework user, I want to group schedule skills into sequential execution groups, so that Planning and Execution phases are never triggered in parallel, preventing file conflicts and race conditions.

**背景**
Sprint 18 交付的 schedule skill 支援單一 skill 排程，但 Planning 與 Execution 若同時觸發會造成衝突（同時讀寫 sprint_N.md 等共享檔案）。本 Story 引入「序列鎖」機制，透過 group 綁定確保同群組內的 skill 不平行執行。Architect 已建立 AC。

| # | 類型 | 條件 | 通過標準 |
|---|------|------|----------|
| AC1 | [靜態] | 序列鎖使用說明 | schedule SKILL.md 新增「序列鎖」使用說明：觸發語法 `--sequential-group`、group 綁定方式、鎖行為描述（同群組內序列執行） |
| AC2 | [靜態] | 模板新增 group-level flock | 生成腳本模板新增 group-level flock：group 鎖路徑定義、`flock -n` 嘗試取鎖、取鎖失敗時輸出 SKIPPED 並退出 |
| AC3 | [靜態] | Pre-flight group 衝突偵測 | Pre-flight 新增 group 衝突偵測：偵測相同 group 是否已有執行中的排程，衝突時阻擋部署 |
| AC4 | [靜態] | Log 格式新增 group 資訊 | Log 格式新增 group 欄位，每次執行記錄所屬 group（無 group 時記錄 `none`） |
| AC5 | [靜態] | ADR-005 更新 | ADR-005 決策域二更新「跨 Skill 序列鎖子節」，記錄序列鎖設計決策與 group 綁定機制 |
| AC6 | [動態] | 回歸驗證 | 無 `--sequential-group` 參數時，schedule skill 行為與 Sprint 18 交付版本完全一致（回歸不破壞現有功能） |

**MoSCoW**：Should / **Size**：M / **Points**：2
**來源**：GitHub Issue #50
**ADR**：ADR-005（延伸，決策域二更新）
**依賴**：Retro #53 完成後執行（Phase 2 序列）
