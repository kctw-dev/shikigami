# 可及性要求（WCAG 2.1 AA）

> 摘錄自 `skills/uiux-designer/SKILL.md`（§4.0 首次使用者建立指引 + §4.4 覆蓋要求）

## 基準標準

所有 DESIGN Story 的 Figma Prototype 必須符合 **WCAG 2.1 AA** 基準。

## 1. 顏色對比度

| 對象 | 最低對比比 | 備註 |
|------|-----------|------|
| 正文文字（< 18pt） | 4.5:1 | WCAG 2.1 AA 標準 |
| 大型文字（≥ 18pt 或 14pt Bold） | 3:1 | WCAG 2.1 AA 標準 |
| 非文字 UI 元素（圖示、邊框） | 3:1 | 按鈕邊框、輸入框邊框等 |
| 禁用狀態 | 豁免 | 禁用元素無對比度要求 |

**驗證方式**：使用 Figma Plugin（如 Contrast）或手動計算相對亮度比。

**Vision Critic 評分影響**：顏色對比度違規會影響 Token 合規維度（佔 40%）。

## 2. 鍵盤導航

| 要求 | 說明 |
|------|------|
| 焦點可見性 | 所有互動元素必須有明確的 Focus 狀態視覺指示（不得移除 outline） |
| Tab 順序 | 焦點順序應符合視覺閱讀順序（左→右、上→下） |
| 逃逸路徑 | Modal / Dropdown 必須支援 Esc 鍵關閉 |
| 跳過導覽 | 長頁面應提供「跳至主要內容」連結（Prototype 規格中標注） |

**Prototype 標注方式**：在 Figma Frame 的 Description 欄位標注鍵盤導航順序與快捷鍵規格。

## 3. 色彩不得作為唯一資訊載體

| 場景 | 合規做法 | 不合規做法 |
|------|---------|-----------|
| 表單錯誤 | 紅色邊框 + 錯誤圖示 + 錯誤文字 | 僅紅色邊框 |
| 狀態指示 | 顏色 + 標籤文字（如「● 進行中」） | 僅顏色圓點 |
| 圖表資料 | 顏色 + 圖案填充或資料標籤 | 僅顏色區分 |

## 4. 文字可及性

| 要求 | 說明 |
|------|------|
| 最小字級 | 正文 14px（行動端 16px）；輔助文字 12px（限制使用） |
| 行距 | 最小 1.5×字級（正文段落） |
| 字距 | 不得壓縮至負值 |
| 文字截斷 | 長文本截斷必須提供完整文字的 Tooltip 規格 |

## 5. 互動元素最小尺寸

| 元素類型 | 最小觸控目標 | 說明 |
|---------|-----------|------|
| 按鈕 | 44×44px | 含 padding 計算 |
| 連結 | 44×44px（行動端） | 桌面端 24px 可接受 |
| 圖示按鈕 | 44×44px（含觸控區域） | 視覺圖示可小於 44px，但點擊區域需達標 |
| 核取方塊 / 單選鈕 | 24×24px（視覺）/ 44×44px（觸控） | — |

## 6. 表單可及性

| 要求 | 說明 |
|------|------|
| 標籤關聯 | 每個輸入欄位必須有明確標籤（非僅 placeholder） |
| 錯誤訊息 | 錯誤訊息必須明確描述問題與修正方式，位置緊鄰對應欄位 |
| 必填標示 | 必填欄位以 * 標示，並在表單頂部說明 * 代表必填 |
| 驗證時機 | 規格中明確標注「即時驗證（onBlur）」或「提交後驗證（onSubmit）」 |

## 7. Prototype 可及性覆蓋要求（QA Contract Testability 標準）

DESIGN Story 的 Prototype 必須包含以下可及性相關 Frame：

- [ ] **Error State Frame**：每個表單的驗證失敗狀態（含錯誤訊息位置與文字）
- [ ] **Focus State**：主要互動元素的鍵盤焦點樣式
- [ ] **Empty State**：列表/資料區塊的空狀態 UI
- [ ] **Loading State**：非同步操作的載入中狀態

## 8. 高風險 UI 強制人工審查

以下頁面即使 Vision Critic 評分通過，仍必須升級人工 Review（ADR-016 HG-D6）：

- 付款流程
- 資料刪除確認對話框
- 帳號權限設定頁面

此類頁面可及性錯誤的業務影響遠高於視覺評分能捕捉的範圍。
